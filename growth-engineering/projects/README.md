# Projects

Six build briefs. Each one produces an artefact you can show somebody, takes between a day and a
fortnight, and is deliberately specified without a solution, because the decisions are the point.

Do them on a real product. Your own if you have one, and otherwise a product you use daily, where
you can see the funnel from the outside and reason about what must be true inside it. Working on a
fictional company removes the only hard part, which is that real numbers disagree with each other.

| # | Project | What you end up with | Time |
|---|---|---|---|
| 1 | [A growth model for a real company](01-growth-model.md) | One spreadsheet and a page of dated assumptions | 2 days |
| 2 | [A tracking plan for an app you use](02-tracking-plan.md) | A grammar, twenty events and a monitoring plan | 3 days |
| 3 | [A teardown of one onboarding flow](03-onboarding-teardown.md) | A step table, a cliff and a costed recommendation | 1 day |
| 4 | [A channel test design somebody would fund](04-channel-test.md) | A test plan with a decision rule and a budget | 1 day |
| 5 | [An experiment result memo for a test you did not run](05-result-memo.md) | An eight part memo and a replication estimate | Half a day |
| 6 | [A margin model for a product with a model in it](06-margin-model.md) | A breakeven use count and a cohort profit curve | 2 days |

Projects 1 and 2 are the two worth doing first, in that order, because every other project assumes
you can read a model and trust an event.
